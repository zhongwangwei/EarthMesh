# CMRC 实际组件事务影子回放（2026-10-21）

继[历史组件移动域审计](cmrc_component_domain_audit_20261021.md)后，本轮验证四点候选能否在组件127、目标层级1的真实事务状态中通过认证。结果为 **Changed 与 Whole 两条认证路径均接受，克隆提交后的完整网格和交付等级一致**。两条路径本例均使用完整工作网格（`window=false`），不能据此声称紧凑 Window 回放已经验证。优化器继续私有、默认关闭；未发布新版本。

## 方法与隔离范围

以 `db927307af6b46676659b960e89a0fa538cf8baf` 归档源码应用私有 overlay。同一二进制顺序执行 control、最终质量候选捕获、真实事务影子回放。使用既有原生约90 m MERIT、LANDTYPE及635,769个实际发布单元的固定选择文件，区域和需求参数延续前轮；没有替换为30 m数据。离散层级的实际最细名义尺度仍约125.005 m。

捕获只发生在四点候选通过原始 Lattice 源需求、fresh remap 与完整最终认证之后。记录原 fine 指纹、组件／层级及四个原始 source ID 的原坐标和候选坐标 f64 位值。真实事务回放在该组件原候选认证成功、原提交尚未执行时，从克隆的事务前态开始：刷新完整状态，再分别重建 Changed 和 Whole 工作网格，执行同一个 transition 和原弹性求解。

四点此时的坐标必须逐位等于捕获原坐标，属于当前允许移动域、不在固定集内，且当前 guard 不触及人工切口。每点位移按当前邻边尺度重新检查3%上限；验证全部通过才注入坐标。全部相关 guard 与 moved faces 合并去重后，同时用于局部几何认证、changed faces、边缘范围及 interval-box 预算。后续源需求、局部／Whole 几何和 fresh remap 认证复用 `certify_candidate`。

成功的影子事务只提交到克隆状态并刷新，用完整网格指纹和交付等级哈希比较两路径。原事务、scheduler、重试计数及最终网格不接受影子结果。独立验收从原始文本重新核对坐标、集合、位移、预算与提交证据，再严格比较实际输出，而非只信任 `accepted=true`。
