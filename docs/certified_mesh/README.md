CMRC (`refine_backend = 'certified'`) is a peer of Method-C, Red-Green, and
HARP-DV. Selecting it does not rename, replace, or downgrade another backend.

The backend starts from a radially projected integer subdivision of a regular
icosahedron and turns every requirement into a conservative minimum level. The
reverse path uses a complete global 2:1 hierarchy rebuild for uniform fields
and finite one-site cavities for nonuniform fields. A mixed cavity commits only
after deterministic transition-block relocation restores the strict geometry
window and exact final-cell requirements pass; otherwise the finer state is
retained.

## Publication gate

A formal CMRC gridfile may be published only from one
`CertifiedPrimalDualMesh` whose combined certificate reports all of the
following:

| hard check | required value |
|---|---:|
| triangle angles below 40 degrees | 0 |
| triangle angles above 80 degrees | 0 |
| physical residuals | 0 |
| balance residuals | 0 |
| vertex degree outside 5..=7 | 0 |
| open edges | 0 |
| topology errors | 0 |
| Euler characteristic | 2 |
| sum of `(6 - degree)` | 12 |
| invalid Voronoi cells | 0 |
| primal-dual reciprocal adjacency errors | 0 |
| conservative-remap closure errors | 0 |

Construction uses the stricter internal angle window 40.2--79.8 degrees. The
publication check repeats the test against the requested 40--80 degree window.
Triangular, Voronoi, and coupled deliveries are views of the same certified
object; they are not generated by independent mesh paths.

The canonical gridfile already carries both its triangular M records and
Voronoi W records. `coupled` therefore means both certified views in that one
file, rather than two independently generated files. Before publication, the
CLI checks that every written W site, M circumcentre, and reciprocal incidence
matches the certified primal-dual object.

The CLI converts every accepted requirement source to a typed raster level
field and binds physical/balance evidence to the final Voronoi cells. The
currently published uniform meshes use the conservative global raster maximum
as every final-cell lower bound. The certified core also supports exact
spherical raster-to-Voronoi overlap for mixed target level fields; seam, polar,
pentagon, close-hotspot, noisy, and ring cases are regression tested. Mixed
local meshes use that exact overlap certificate at the publication gate.

Finite one-site cavities now have bounded `Feasible`, `ProvenInfeasible`,
`SearchBudgetExhausted`, and `InvalidBoundary` outcomes; every accepted cavity
atomically certifies geometry, final-cell physical/balance requirements, and
Voronoi remap closure. Deterministic epochs attempt each stable candidate once,
retry only dirty one-rings, stop after a zero-commit epoch, and promote blocked
transition components by retaining the fine level. Candidate budgets are
isolated under a total epoch budget, so one exhausted candidate does not stop
later candidates from being attempted. Regular hierarchy one-site
retirement uses a bounded deterministic relocation of its retained ring and
transition halo when fixed coordinates do not satisfy the internal angle and
degree windows. The original twelve icosahedron vertices and their one-rings
are protected from this relocation for output compatibility.

The CLI publication order is fixed:

```text
temporary mesh/remap/certificate/manifest/resource artifacts
-> combined certificate passes
-> remap certificate passes
-> publish the certificate
-> publish the remap
-> publish the formal gridfile
-> publish the resource report
-> publish the manifest
-> publish the ready marker last
```

Before replacement, an existing generation is backed up with its ready marker
made unavailable first. A returned publication error removes only artifacts
from the new attempt, restores the previous generation byte-for-byte, and
restores its ready marker last. The ready marker is the availability signal.
This is rollback-safe for ordinary I/O errors, not process-crash or power-loss
atomic; that stronger guarantee would require generation directories and one
final pointer swap.

## Failure outcomes

The typed API distinguishes:

- `CertifiedAdaptive`
- `CertifiedSafeFallback`
- `CompressionIncomplete`
- `CellBudgetInsufficient`
- `MaximumLevelReached`
- `CriterionNotCertifiable`
- `PhysicalCriterionUnsatisfiable`
- `UnsupportedBoundaryConstraint`
- `SearchBudgetExhausted`
- `InternalCertificationFailure`

`SearchBudgetExhausted` means only that a bounded local compression search
stopped; it is not proof that the requested coarsening is impossible. Mixed
requirements delivered as a uniform mesh are `CompressionIncomplete` and do
not publish an ordinary success file. Explicit `safe_mother_only` delivery may
publish the certified mesh under `*_certified_safe_fallback.*` names instead.
