## 3. 未完成的工作（按优先级）

### 3.1 所有算法的最终网格：合格线 35°–85°，目标趋近 60°——已实施（2026-09-26，指南 11.74）

用户已确认并要求开工。实现与实测见指南 11.74；下面保留当初的分析供参考。剩余：大网格上第二阶段的
耗时优化；LEPP 网格度数 7 顶点导致 ICON 交付失败（LEPP 自身问题）；CMRC 流水线不经过统一步骤。

#### 原分析

用户的原话要点：**35°–85° 针对最终网格、针对所有算法，过程怎样不管；算法里要不断提高角度的完美程度，
落在 35°–85° 算合格，都逼近 60° 最好。**

现状：
- 质量判定对所有算法生效（`earthmesh_quality::TRIANGLE_ANGLE_WINDOW_DEG`，写在阈值默认值里）。
- 修复只接在 Red-Green 上，而且目标是“到窗口的余量”，一进窗口就停，结果贴着边：35.25°–84.75°。
- 各算法三角形输出实测：Method-C Canonical 37°–83°（Case9）；Red-Green 修复后 35.25°–84.75°；
  CMRC 由证书保证 40°–80° 或 38°–82°；**LEPP 28.71°–117.09°，被判失败**（`lepp_tri_global`）。

计划（已向用户说明，待其说“开始”）：
1. 修复的目标函数改为趋近 60°：进窗口后继续优化（例如最大化最小角、最小化最大角，或最小化与 60° 的
   偏差），直到局部改不动。原型证据（Python 原型，未入库，数据见指南 11.73 的表）：按最差余量的模式搜索在 Case9
   切割前网格上把 58,223 个出界三角形压到 28 个，说明局部优化空间很大。
2. 放在**输出层一处**、对所有算法的最终三角形网格统一执行（`refine_pipeline/outputs.rs`
   `write_refined_outputs` 写 gridfile 之前；CMRC 走 `run_certified_pipeline`，要另外接或证明不需要）。
   Hex 输出不受三角形窗口约束。
3. 需要处理的技术点：
   - 翻边/删顶点会改变行：要把每行记录跟着重映射——`cell_levels`（M 行取来源面最深、W 行按顶点）、
     Method-C 的谱系/原始层级/`ngr`（`MethodCMetadataSlices`）、`hard_center_demand`（tri 下按 M 行）。
     做法：修复函数返回“每个输出面/顶点来自原来哪一行”（曾写过一半 `repair_triangle_angle_window_traced`
     + `AngleWindowOrigins`，因方向调整已撤回，未提交）。
   - 三角形中心（M 点）约定不同：Method-C/LEPP 为外心（PCVT），Red-Green 为球面形心；只重算被改动的面。
   - W 环顺序：改拓扑后重建 `w_to_m`，再用 `outputs.rs::oriented_spherical_native_w_rings` 定向。
   - 五边形顶点（`pentagon_indices`）不能删，且删点压缩 id 时不能让它们的编号变化。
   - 切割（海洋/陆地 carve）只删单元、不改角度，所以在切割前做即可。
4. 会改变现有输出（原本合格的网格也会被继续优化），A/B 不再逐位一致；要报告改动前后角度分布
   （最小/最大角、与 60° 偏差的均值与分位数）作为证据，并给质量报告加上“偏离 60°”统计。
5. 之后 Red-Green 自身的末端修复可以并入这一处统一步骤。
