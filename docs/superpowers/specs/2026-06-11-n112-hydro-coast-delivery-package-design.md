# N112 Hydro/Coast Delivery Package Design

## Purpose

Promote the current `N112_r3d3_cst20` Yangtze-delta hydro/coast candidate from a collection of scratch artifacts into a reproducible EarthMesh v3 delivery package. The package should be generated by one Python command from existing GeoJSON/log inputs, so future CoLM2024/CoLM20XX, MPAS, FVCOM, and QA workflows can reference stable outputs instead of hand-maintained HTML paths.

## Scope

This design covers packaging and reproducibility only. It does not rerun `mkgrd.x`, repair the N128 close-curve failure, or write final model-native NetCDF files. It consumes already-generated EarthMesh cell intersection GeoJSONs and refinement logs.

## Architecture

Add a small hydro utility module, `util/hydro_mesh/refinement_package.py`, beside the existing `refinement_eval.py`, `refinement_sweep.py`, and `geojson_map.py` modules. The new module orchestrates three existing capabilities:

1. `write_refinement_eval_json()` to create a coast-aware evaluation JSON.
2. `mesh_geojson_to_leaflet_html()` to create an integrated river/coast/background QA HTML.
3. `write_sweep_ranking()` to write a ranking JSON, optionally including extra comparison or failed reports.

The module writes a final `delivery_manifest.json` listing all package files, source inputs, case metadata, and the recommended case. This manifest is the adapter handoff surface for later CoLM2024/20XX coupling work.

## CLI shape

The first command is intentionally file-based and explicit:

```bash
python3 -m util.hydro_mesh.refinement_package \
  --case-name N112_r3d3_cst20 \
  --background-geojson <background.geojson> \
  --river-geojson <river-overlap.geojson> \
  --coast-geojson <coast-overlap.geojson> \
  --log-path <mkgrd.log> \
  --output-dir <package-dir> \
  --title "Yangtze delta N112 hydro/coast EarthMesh cells" \
  --comparison-reports <optional existing eval jsons...> \
  --failed-reports <optional failed eval jsons...> \
  --max-background-cells 3000
```

## Outputs

For case `N112_r3d3_cst20`, the package directory contains:

- `N112_r3d3_cst20_refinement_eval.json`
- `N112_r3d3_cst20_rivers_and_integrated_coast_leaflet.html`
- `refinement_sweep_ranking.json`
- `delivery_manifest.json`

`delivery_manifest.json` contains:

- `kind = earthmesh_hydro_coast_delivery_package`
- `case_name`
- `recommended_case`
- `files.eval_json`
- `files.html_map`
- `files.ranking_json`
- `source_files.background_geojson`
- `source_files.river_geojson`
- `source_files.coast_geojson`
- `source_files.log_path`
- summary metrics copied from the generated eval JSON: background cell count, river overlap cells, coast overlap cells, and retained triangles.

## Error handling

The command validates that all required source files exist before writing outputs. Missing required inputs raise `FileNotFoundError` with the missing path. Comparison and failed reports are read only when provided; missing optional report paths are still errors because otherwise the ranking would silently omit intended evidence.

## Testing

Add `tests/test_refinement_package.py` with small synthetic GeoJSON fixtures. Tests should verify:

1. The package writer creates eval, HTML, ranking, and manifest files.
2. The manifest records source paths, package file paths, recommendation, and copied metrics.
3. The CLI returns `0` and writes the same package surface.
4. Missing required inputs fail before partial package assumptions are made.

## Future extension

After this package layer exists, the next step is a CoLM2024/CoLM20XX coupling table writer that reads `delivery_manifest.json` plus the same river/coast EarthMesh overlap files and writes stable cell-level CSV/NetCDF metadata. That coupling writer should not depend on scratch naming conventions.
