# CoLM Coupling Package Table Design

## Purpose

Turn a hydro/coast delivery package into a stable CoLM2024/CoLM20XX coupling table. The table should let downstream model-adapter work consume one row per EarthMesh cell, with river, coast, and background metadata joined by `cell_id`.

## Scope

This is a metadata table, not final CoLM NetCDF forcing or grid input. It does not change mesh generation, does not rerun `mkgrd.x`, and does not resolve the N128 close-curve failure. It consumes `delivery_manifest.json` generated by `util.hydro_mesh.refinement_package`.

## Architecture

Extend the existing `util/hydro_mesh/colm_coupling.py` module rather than adding a parallel implementation. Keep the current river-only CSV/JSONL API intact for backward compatibility. Add a manifest-driven writer that reads:

- `source_files.background_geojson`
- `source_files.river_geojson`
- `source_files.coast_geojson`
- package-level `case_name` and `recommended_case`

The writer builds a dictionary keyed by `cell_id`, starts from all background cells, and overlays optional river and coast metadata. River and coast overlap rows can be sparse; background cells with no river or coast overlap still appear with empty coupling fields. This preserves the all-cell mask principle required for CoLM/20XX handoff.

## Output files

The new command writes:

- `colm_coupling_cells.csv` — one row per background EarthMesh cell.
- `colm_coupling_summary.json` — counts and source references.

Core CSV fields:

- `case_name`
- `cell_id`, `cell_index`, `center_lon`, `center_lat`
- `surface_class`
- `has_river`, `river_class`, `river_fraction`, `estimated_river_area_m2`
- `has_coast`, `coast_class`, `coastal_fraction`
- `normalized_cell_area_m2`, `source_areaCell`, `source_areaCell_units`

`surface_class` is conservative in this phase: `COAST` if the cell has coast overlap, otherwise `UNKNOWN`. Land/ocean separation should be added later from MERIT or CoLM land/ocean masks.

## CLI shape

```bash
python3 -m util.hydro_mesh.colm_coupling package \
  --delivery-manifest <package>/delivery_manifest.json \
  --output-dir <package>/colm_coupling
```

The existing positional river-only CLI remains available.

## Tests

Add tests proving:

1. A package manifest writes all background cells, including cells with no river/coast overlap.
2. River and coast metadata are joined into the same row when they share a `cell_id`.
3. The package CLI writes both CSV and summary JSON.
4. Existing river-only tests continue to pass.
