# CMRC 后期认证失败的弹性计数修复（2026-10-26）

沿用[实际采用验证](cmrc_actual_adoption_20261021.md)的后续失败路径检查，发现生产事务存在统计漏记：弹性调整成功并写入候选Work之后，若后续认证失败，错误报告保留interval boxes却将elastic iterations留为0。外层事务及调度器直接累加错误报告，因此这些已执行的迭代从汇总中消失。

## 修复

在 `certify_candidate` 的10处后期失败报告中补上已完成的 `elastic_iterations`，覆盖局部/全局/最终几何、Changed/Window单元检查、目标等级、重映射及证据、最终单元和提交前置条件。复用已有错误报告字段，没有增加接口、开关或依赖。

这是报告准确性修复。弹性迭代上限按拓扑候选独立计算，不能把累积报告数从下一候选上限中扣除；现有预算语义及重试规则保持不变。生产优化器未因此启用。

## 回归范围

新增 `late_cell_rejection_retains_state_and_charges_applied_elastic_work`，复用真实ringed component与弹性求解器，不使用模拟错误钩子。在Whole和Changed认证模式下分别验证：

- 同一候选在较低需求下认证成功，发生实际顶点移动且弹性迭代大于0。
- 提高最终单元需求后，候选经过相同移动，在FinalCells阶段以Retry拒绝。
- 失败报告的弹性迭代及interval boxes与同候选成功路径一致；候选网格和移动集合相同。
- 完整原始ComponentTransactionState仍相等，丢弃失败Work后，以正常需求重新求解，与干净对照的状态和报告一致。

此测试直接调用候选认证器，验证真实移动后的拒绝及状态隔离。它不证明失败经外层调度器重试后的行为，也不替代私有四点注入路径的后期失败端到端试验。
