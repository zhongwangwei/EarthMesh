# EarthMesh GUI 改版建议（布局重规划 + 视觉体系）

> 配套交付：`prototype.html`（可交互原型，含明/暗双主题、中英切换、Normal/Expert）。
> 上游设计：[10_gui_redesign_proposal.md](../reviews/v3_mesh_audit/10_gui_redesign_proposal.md)（IA/工作流）、[R9 报告](../reviews/v3_mesh_audit/fix_reports/R9_gui_workflow_visual.md)（已落地的设计系统/模板/仪表盘）。
> 证据基准：`rust/earthmesh_gui/src/{main.rs, theme.rs, i18n.rs, ui_helpers.rs, components.rs}`。

---

## 1. 现状诊断：为什么"没法看"

当前 `update()`（`main.rs:3558-3830`）把界面拆成**四个面板围住一个中心**，再加一条塞满控件的顶栏：

| 区域 | 代码 | 问题 |
|------|------|------|
| 顶栏 | `:3565-3660` | 标题＋项目名＋Run＋Cancel＋Load＋Save＋输出目录＋搜索框＋模板下拉＋语言＋主题＋Expert **挤在一行**（11+ 控件） |
| 底部 dock | `:3692-3735` | 质量/耦合/细化/Hydro 四个折叠区，可占**半屏**（`dock_max = height*0.5`） |
| 左栏 cases | `:3737-3775` | 190px，模板＋最近文件 |
| 右栏 run | `:3777-3815` | 300px，状态＋进度＋日志 |
| 中心 | `:3817-3829` | Basics/Refinement/Advanced **三 tab 密集表单**（~64 字段） |

**算一笔账**：默认窗口 1040×680（`:3835`）。横向减去左 190 + 右 300 ≈ 剩 ~550px；纵向减去顶栏 + 底部 dock 220（可到半屏）≈ 中心只剩 ~300px 高。**真正干活的表单被压在一个 ~550×300 的格子里，还要塞 64 个参数**——这就是"灾难"的来源。

两个深层问题：

1. **布局**：四面板同时常驻，互相挤压，没有主次。中心是最该大的，却最小。
2. **心智**：界面是一张"引擎参数表单"，用户被迫一次面对全部 64 个旋钮（NXP/HALO/transition/spring/num_rc…），没有"我想要什么网格 → 一步步来"的流程感（[10 提案 §1](../reviews/v3_mesh_audit/10_gui_redesign_proposal.md)，U1/U2）。

**美观**层面：`theme.rs` 目前只在用户手动切换时 `set_visuals(Visuals::light/dark)`（`:104-116`），启动仍用 egui 默认外观；色板/间距/卡片虽已定义（`PASS/WARN/FAIL`、`Spacing::SCALE`、`card_fill`）但**没有真正贯穿到布局**，所以整体观感是"未加工的 egui 默认控件堆叠"。

> 好消息：R9 阶段其实已经把**地基**打好了——`theme.rs`（明/暗 + 状态色 + 图层色 + 间距）、`components.rs`（`status_badge`/`card`/`section_header`/`empty_state`）、`ui_helpers.rs`（9 个模板 + **7 步工作流模型** `workflow_steps()` + 质量仪表盘解析）都在，但**没接进布局**（R9 §8.1：「Workflow 步骤未替换 3-tab 布局」）。所以本次改版主要是 **`main.rs` 的重排**，不是从零造轮子。

## 2. 新布局：三区 + 顶栏 + 状态栏

把"四面板围中心"换成**清晰的三纵区**，上下各一条窄条：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏(52px)  ◈EarthMesh · Project▾ · [项目名]   …  Normal/Expert 中/EN 🌓 ▶Run │
├────────────┬───────────────────────────────────┬────────────────────────┤
│ 左：步骤导轨 │ 中：当前步骤工作区                  │ 右：实时面板             │
│ (248px)     │ (自适应，最大，留白充足)            │ (360px)                 │
│ ① 新建      │  ┌ STEP 5 / 7 ────────────────┐   │ [地图][质量][日志]      │
│ ② 目标 ✓    │  │ 细化策略                     │   │ ┌────────────────┐     │
│ ③ 区域 ✓    │  │ 判据 + 权重滑杆 + 预算        │   │ │ 评分热力图地图  │     │
│ ④ 数据 ✓    │  │ (引擎旋钮折进 Expert 区)     │   │ │ 计算域虚线框    │     │
│ ▶⑤ 细化     │  └─────────────────────────────┘   │ └────────────────┘     │
│ ⑥ 质量      │  [← 上一步]          [下一步 →]    │ 图层: 评分/网格/海岸   │
│ ⑦ 运行/结果 │                                   │                        │
├────────────┴───────────────────────────────────┴────────────────────────┤
│ 状态栏(34px)  ●Pass · 412k cells · 预算▓▓▓░ 58% · ✓输入有效        ○idle │
└──────────────────────────────────────────────────────────────────────────┘
```

**为什么这样能解决问题**：

- **中心变大**：左 248 + 右 360，中心仍有 ~430px 且**纵向不再被底部 dock 吞**（结果并入右栏「质量」tab 和状态栏）。配合"一次只显示一个步骤"，中心从"塞 64 字段"变成"一屏一件事"。
- **顶栏瘦身**：原来一行 11 控件 → 拆成「顶栏只放 Project/模式/语言/主题/Run」+「状态栏放运行态/预算/校验」。搜索、模板、输出目录等移入对应步骤或菜单。
- **左栏升级**：cases 列表 → **7 步工作流导轨**（带序号圆点、完成打勾、当前高亮、连接竖线）。模板/最近文件并入步骤 ①②。
- **右栏合并**：原「右栏 run」+「底部 dock」→ 一个 tab 化的「实时面板」（地图 / 质量 / 日志），随时可看，但不再四面挤压。

**7 步**直接复用 `ui_helpers::workflow_steps()` 与 `i18n.rs` 已有的 `step.*` 键：
新建项目 · 目标 · 区域 · 数据图层 · 细化策略 · 质量约束 · 运行/结果。

**渐进式披露（修 U2）**：Normal 模式每步只显示"意图"（目标/域/数据/质量目标/预算）；NXP/HALO/spring/num_rc/手动掩膜等引擎旋钮全部折进每步内一个**虚线描边的 Expert 区**（顶栏开关一键显隐）。切回 Normal 不丢 Expert 设置。

## 3. 视觉体系：明 / 暗双主题 Design Tokens

沿用 `theme.rs` 现有品牌色（GitHub Primer 风，已是好底子），补成完整 token 表。原型 `prototype.html` 的 CSS 变量与此一一对应，可直接搬进 egui 的 `apply()`。

### 配色

| Token | Light | Dark | 用途 |
|-------|-------|------|------|
| bg | `#ffffff` | `#0d1117` | 窗口底 |
| surface | `#f6f8fa` | `#161b22` | 顶栏/左右栏/状态栏 |
| elevated | `#ffffff` | `#1b2230` | 卡片 |
| border | `#d0d7de` | `#30363d` | 描边 |
| text / muted | `#1f2328` / `#656d76` | `#e6edf3` / `#8b949e` | 文字 |
| **accent** | `#1f6feb` | `#58a6ff` | 主色（当前步/按钮/滑杆）— 同 `theme.rs::accent()` |
| pass / warn / fail | `#1a7f37` / `#9a6700` / `#cf222e` | `#3fb950` / `#d29922` / `#f85149` | 状态 — 对应 `PASS/WARN/FAIL` |

图层色（地图/图例）直接用 `theme.rs::layer_color()`：land `#78aa5a` · ocean `#3c78c8` · river `#288cc8` · coast `#dc963c` · estuary `#b464c8` · urban `#b44646`。

### 间距 / 圆角 / 字号

- 间距：`xs2 sm4 md8 lg16 xl24`（= `Spacing::SCALE`，已存在）。卡片内 16，区块间 16–24。
- 圆角：控件 6px、卡片 10px。
- 字号：正文 13.5、卡片标题 14、步骤标题 23、指标数字 21；标签 11–12 用 muted。
- 卡片：`elevated` 底 + 1px `border` + 轻阴影（暗色用更深阴影）。状态徽章 = 圆角药丸 + 对应状态色浅底。

### 三条"上档次"的小规则

1. **留白**：步骤工作区四周 24–28px padding；字段间 13px。当前界面最缺的就是呼吸感。
2. **层级**：同屏最多一个主色（accent）焦点；其余用 muted/border 退到背景。Expert 区用虚线 + 极淡主色底，和 Normal 内容明确区分。
3. **一致的状态语言**：Pass/Warn/Fail 在状态栏徽章、质量仪表盘、地图图例、日志里**同色复用**（已有 `status_color()`，贯穿即可）。

## 4. 落地映射（改动集中在 main.rs）

| 模块 | 现状 | 改动 |
|------|------|------|
| `theme.rs` | 明/暗 + 状态/图层色 + 间距已定义 | **启动即 `apply()`**；补 elevated/muted/圆角等 token；Expert 区底色 |
| `components.rs` | badge/card/section_header/empty_state 已有 | 新增 `stepper(steps, cur)`、`metric_card`、`pill_toggle`、`expert_zone(ui, ...)` |
| `ui_helpers.rs` | 9 模板 + `workflow_steps()`(7) + 质量解析已有 | 补每步"字段→ProjectConfig 子结构"的映射；预算→预计 cell 数估算 |
| `i18n.rs` | `step.*`/`tpl.*`/`dash.*`/`mode.expert` 已有 | 按 [10 §11](../reviews/v3_mesh_audit/10_gui_redesign_proposal.md) 补 `wizard./layer./strategy./preview./quality.` 命名空间 |
| **`main.rs`** | 四面板 + 3 tab（`:3565-3830`） | **核心重排**：顶栏瘦身 → 左 `stepper` 替 cases → 中心按 `cur_step` 渲染单步（Normal/Expert 分支）→ 右栏 tab 化（地图/质量/日志）→ 底部 dock 收为状态栏。旧 3 tab 的 64 字段**整体迁入各步的 Expert 区，零功能丢失** |

> egui 完全够用：纵向 stepper = 带圆点的 `vertical` 列表；卡片 = `egui::Frame`；滑杆/下拉/折叠均原生；地图沿用 `walkers` `MeshOverlay`（`:698-996`）。原型里的每个控件都能在 egui 复刻。

## 5. 实施顺序（每步可回归、不丢旧能力）

1. **G-0 视觉接通**：`theme.apply()` 启动即调 + token 补全。低风险、立刻变好看。
2. **G-1 骨架**：顶栏瘦身 + 状态栏 + 右栏 tab 化（地图/质量/日志）。中心暂留旧 3 tab。
3. **G-2 步骤导轨**：左栏换 `stepper`，点击切步；中心按 `cur_step` 渲染。**旧 3 tab 内容原样塞进对应步骤**（先不拆 Normal/Expert）。
4. **G-3 渐进披露**：每步把引擎旋钮折进 Expert 区，Normal 只留意图字段。
5. **G-4 模板/数据/预算**：步②模板卡、步④数据图层管理器（覆盖校验）、步⑤预算→预计 cell 数。
6. **G-5 仪表盘/地图预览**：步⑦质量仪表盘（已有解析）、右栏 score 热力图。

G-0/G-1 一两天即可让界面"能看 + 好看"；后续按工作流深化。
